Excel #REF! — what it means and how to find the rest

A #REF! is Excel saying "this formula used to point at something that no longer exists". It is a deletion scar, and one visible scar almost always means others are hidden.

What causes it

  • A row, column or cell that a formula referenced was deleted.
  • A sheet a formula referenced was deleted or renamed in a way Excel could not follow.
  • A cut-and-paste that moved the source out from under the formula.
  • A formula was written by another tool against a range that does not exist in this workbook.

Excel is careful about the last one: the error is not "my reference is wrong", it is "my reference was right and something removed it". That is why the fix is rarely just retyping the address.

Find every occurrence, not just the one you can see

  1. Find across formulas. Press Ctrl+H, put #REF! in Find what, and set Look in to Formulas (not Values). Choose Find All to get the full list at once.
  2. Check every sheet, including hidden ones. Ctrl+H searches the whole workbook, which is the main reason it beats scrolling.
  3. Look for the silenced version. A formula wrapped in IFERROR(…, 0) will show a clean zero instead of an error. That is the dangerous case: the sheet looks healthy and the number is a placeholder.
  4. Check external links. Data → Edit Links lists workbooks this file depends on. If the source moved, every formula reading it is broken even without a visible error.

Fixing it properly

If the deletion was accidental, Ctrl+Z immediately is the only reliable repair — it restores both the cells and the references pointing at them.

If the deletion was intentional, the formula needs to be rewritten, not patched. Decide what the cell should now mean:

  • Point at the new location — retype the reference and confirm the number reconciles to what you expect.
  • Make it explicit that the input is gone — a deliberate NA() or a blank is honest; a silent 0 is not, because it flows into totals as if it were real.
  • Re-check the totals downstream — trace dependents on the repaired cell. A #REF! that was feeding a sum was quietly making that sum too low, and anything built on it inherited the error.
The uncomfortable one: saved files with cached results Excel stores the last computed value alongside each formula. If a file was saved before a reference broke — or was produced by a tool that wrote formulas without results — the visible number can be stale while the formula is already broken. Reading the formula, not the displayed value, is the only way to know.

A quick audit sequence for a received file

Ctrl+H for #REF! in formulas · Ctrl+H for #VALUE! and #DIV/0! the same way · Data → Edit Links for external dependencies · unhide all sheets and repeat · then trace dependents on anything that feeds a reported total.
