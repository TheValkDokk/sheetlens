What does this Excel formula mean?

You do not need to memorise 500 functions. You need one reading order. Applied consistently, the method below decodes almost any formula you will meet in an inherited model.

Read it outside-in, never left to right

A nested formula is a sentence with the main clause in the middle. The outermost function is the verb — it says what the cell ultimately does. Everything inside it is detail supporting that verb.

Take this, which is the shape of half the cells in a pricing model:

=IFERROR(INDEX(Rates!$C:$C, MATCH($A4, Rates!$A:$A, 0)), 0)

Read in four passes:

  1. Outer wrapper: IFERROR(…, 0). Whatever happens inside, if it fails, this cell shows 0 instead of an error. That is the first thing you now know: errors here are silenced.
  2. The actual operation: INDEX(Rates!$C:$C, MATCH(…)). INDEX means "give me the item at this position in this range". So the job is: pick something out of column C on the Rates sheet.
  3. The position: MATCH($A4, Rates!$A:$A, 0). Find the row where column A on Rates equals the value in A4 here, requiring an exact match.
  4. Put it back together: "Look up this row's region in the Rates sheet, return its value from column C, and show 0 if the region is not listed."

The five shapes worth recognising

ShapeWhat it says
IF(cond, a, b)If the condition holds, use a; otherwise use b.
IFERROR(x, fallback)Try x; if it errors, show fallback. Treat any silent fallback as a place where a real problem can hide.
VLOOKUP(key, table, n, FALSE)Find key in the table's first column and return the nth column of that row. The FALSE means exact match — without it you get approximate, which is a quiet way to get wrong numbers.
INDEX(range, MATCH(…))The same lookup as VLOOKUP but immune to inserted columns. This is why serious models prefer it.
SUMIFS(sum, r1, c1, …)Add up sum only for rows that satisfy every range/condition pair.

Three habits that make it fast

  • Click, do not squint. Select the cell and press Ctrl+[ to jump to what it references. Seeing the source range is usually faster than parsing the text.
  • Colour-code by depth. In a long formula, underline the outermost function, then the next one in, then the next. Most confusion is depth, not complexity.
  • Ask what would make it wrong, not what it does. "It returns 0 on failure" is the interesting fact. "It looks up a rate" is not.
Where reading by eye runs out It works for one cell.
