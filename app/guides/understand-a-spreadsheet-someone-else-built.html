How to understand a spreadsheet someone else built

The model works. The person who built it left. You have been asked to change one assumption by Friday. Here is the order that keeps you out of trouble.

1. Map the sheets before you read a single formula

For each tab, answer one question: does it hold data, or does it calculate?

A sheet that is almost all formulas is a layer — it takes inputs and produces numbers. A sheet that is almost all values is an input or an export. A sheet that is hidden and full of formulas is the one that should worry you most: it is driving results you cannot see.

Fast method: step across every tab with Ctrl+Page Down, then press Ctrl+End to see the real used range — people are optimistic about the size of their sheets. Unhide everything: right-click any tab, choose Unhide. A tab you cannot unhide is "very hidden" and needs the VBA editor to reveal.

2. Find the assumptions before you find the arithmetic

Every model has a small number of numbers that actually matter — margin, growth, discount, FX — and a large number of derived numbers. The single most valuable thing you can do in the first ten minutes is locate the real inputs.

An assumption that lives in a labelled input cell is safe: change it, everything recalculates. An assumption that lives inside a formula is a trap, because it does not move when the world moves. Search for it: 

Ctrl + `   (grave accent)  — shows every formula on the sheet
Scan for arithmetic against numerals:   B4*0.2    D7/1.08    F2*1.035

Those are the cells that will still be using last year's rate after everyone has agreed the new one.

3. Look for the four breakage patterns

  • Hardcoded rates — arithmetic against a literal, as above.
  • Volatile functions — TODAY(), NOW(), OFFSET(), INDIRECT(), RAND(). A number that changes every time the file opens cannot be reconciled against last month's version.
  • Broken references — #REF! means a row, column or sheet was deleted after the formula was written. Even if it is wrapped in IFERROR, the number you are looking at may be a fallback, not a result.
  • External links — a formula containing a bracketed workbook name depends on a file you may not have. Check Data → Edit Links.

4. Before you edit, trace what depends on the cell

Select the cell you plan to change and run Formulas → Trace Dependents. Arrows show what reads it. Repeat on each arrow: dependency chains are usually two or three hops deep, and the damage from a careless edit is always at the end of the chain, not the beginning.

Trace Dependents does not follow references across sheets cleanly. For that, follow the references in the formula text — or use a tool that builds the graph for you.

The 15-minute checklist Sheets mapped and all unhidden · one labelled input area identified · no arithmetic against literals · no volatile functions in reported numbers · no #REF! · external links listed · dependents of the cell you are about to change traced. If any line is unresolved, you are not ready to edit.
